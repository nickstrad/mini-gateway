## Release It! checklist

- **Integration points:** `cmd/mgctl` applies `-timeout` (default 10 s) to HTTP admin calls and TCP dial + socket `SetDeadline`; `internal/loadgen/live` applies `DialTimeout` (10 s) for connect/login and `-drain` (5 s) for shutdown, clears socket deadlines after login so open-loop pipelining relies on `drain`/`ctx`, and exercises silent/no-read peers in `TestAFakeThatStopsReadingMakesSendsLateOrUnsent` and `TestAStalledFakeShowsInLatencyFromIntendedSend`.
- **Blocked threads:** `live.Run` closes `r.quit` and every `net.Conn` in `finish()` before `r.wg.Wait()`, unblocking all reader and writer goroutines on normal completion, drain timeout, and `ctx` cancel; `mgctl.Query` defers `conn.Close()`; `mgctl` tier S model checks `Proxy.Finish()` quiesce.
- **Slow responses:** `loadgen` never waits for replies to schedule the next request; unanswered requests at drain end stay counted in `in_flight` and queued ones move to `could_not_send` (conserved); proxy refusals are classified and counted immediately on receipt.
- **Cascading failures:** Not applicable to proxy health/engine paths (no engine code modified); `loadgen` fails fast on setup when `ConnsOpen == 0` and stops dispatching to downed connections (`ConnDown`), counting subsequent ops `could_not_send` in O(1) without redial loops.
- **Chain reactions:** Not applicable here because this chunk adds only external operator tools, dev stack scripts, and report scripts, with no proxy admission or multi-instance routing logic.
- **Dogpile:** Not applicable to proxy pool recovery (no engine/pool code modified); `loadgen` dials once up front (capped by `MaxConns = 4096`) and does not reconnect on connection loss.
- **Self-denial attacks:** `loadgen` opens all `-conns` in parallel at start (capped at `MaxConns = 4096`), then sends strictly at constant `Rate` with no retries; `report.sh` batches all DuckDB checks in one session; `mgctl stats -watch` sleeps `interval > 0` between polls and caps at `MaxWatch`.
- **Force multiplier:** Not applicable here because this chunk adds no automatic control or retry loop.
- **Unbalanced capacities:** Every channel and ring buffer in `internal/loadgen` and `live` has a named bound (`MaxOutstandingCap = 1024`, `c.jobs` cap `MaxOutstanding`, `r.events` cap `Conns * MaxOutstanding * 4`, `MaxClasses = 32` with `other` overflow), with explicit full-buffer rules (`choose` returns false → `could_not_send`; non-blocking send to `c.jobs` → `ConnDown`); `cmd/mgctl` caps HTTP bodies at `maxBody = 64 MiB`, password lines at 1 KiB, and `mgctl.Reply` rows at `MaxRows = 10_000` with `Truncated` count.
- **Scaling effects:** `loadgen` is a single-instance client tool (`Instances: 1`); all labels are bounded (`completed` has 4 fixed outcomes, `errors_by_class` is capped at 32 values including `other`, though see Finding 4 for `check-loadgen-labels.sql`).

- **Unbounded result sets:** `mgctl.Session.Receive` caps kept rows at `MaxRows = 10_000` (tracking `Truncated`) and reads in 32 KiB chunks; `cmd/mgctl` caps admin responses at `64 MiB`; no proxy reply forwarding path is changed in this chunk.
- **Compounds:** No retry loop is combined with any leaky path; the minor overlap in `live.go:finish()` (draining events before closing `r.quit`) cannot leak goroutines or break snapshot conservation because `Tracker` is single-owner and sockets are closed before `wg.Wait()`.
