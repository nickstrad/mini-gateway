## Release It! checklist

- **Integration points:** Every retried request reuses the engine's existing virtual-clock queue (`c.queueT`) and statement (`d.stmtT`) timers clamped to `arrival + timeouts.statement` (`retryClamp`), and statement silence (`TestRetryNeverOnStatementSilence`, `e2e-silent-db-query` with policy on) is never retried.
- **Blocked threads:** Before `statementLost` offers a retry, `leaseFailed` closes the failed database connection (`coreLost`/`closeDB`) and `statementDeadline` moves it to the dirty table (`coreDirty`), so a retried request never holds the failed connection; `retryEnded` runs on all 7 `req = nil` exit paths (though `Quiesce()` itself misses the `RetryPending` check, Finding 3, and 3 exit paths lack unit tests, Finding 4).
- **Slow responses:** When a retried request hits the clamped request deadline while queued it is shed with `53M01` (`TestRetryGrantedJustBeforeTheRequestDeadlineAndBoundedByIt`); when forwarded it triggers `statementDeadline` -> cancel/dirty-table (`TestRetryForwardedStatementEndsAtTheRequestDeadline`); tier S checks fast refusals (`53M03 <= 5ms`, `53M01 <= 110ms`).
- **Cascading failures:** When the breaker is open or half-open, `CoreBreaker.Open()` returns true without consulting `Allow()` (no trial started, no dial, O(1) refusal with `RefusedBreaker`, `TestRetryNeverWhenTheLossOpensTheBreaker`, `TestRetryDecidedWithoutConsultingTheBreakersAllow`); health is unchanged by retries (`TestHealthIsUnchangedByRetries`).
- **Chain reactions:** Not applicable to single-instance chunk 12 beyond draining (`RefusedDraining`, `TestRetryNeverWhileDraining`); 3-instance instance-kill is chunk 13.
- **Dogpile:** Retries are refused while the breaker is open or half-open (`b.cp.p.Breaker() != pool.BreakerClosed`), so retries never pile onto a half-open trial or recovery dial; goodput recovery after the fault window is asserted in `checkRecovery` (tier S) and `TestTierRRetryStorm` (tier R).
- **Self-denial attacks:** Retries are off by default, capped at once per request, and rate-governed by the integer token budget (10% of first attempts + floor, capped so a quiet hour cannot bank a storm: `TestAQuietHourCannotBankAStorm`, `TestPathologicalSignalEveryRequestFailingPreForwardStaysUnderTheBound`).
- **Force multiplier:** The retry budget governor has a floor (`retry.floor / N`), ceiling (`retry.bucket_cap`, excess counted in `Expired`), fixed deposit/withdraw step (1/10 vs 1 token), once-per-request bound, and pathological-signal test (`TestPathologicalSignalEveryRequestFailingPreForwardStaysUnderTheBound`).
- **Unbalanced capacities:** A granted retry re-enters `enqueue` (the tenant's bounded admission queue) with no separate retry buffer or timer queue; queue overflow sheds cleanly with `53M01`.
- **Scaling effects:** Stated for N instances in `NOTES.md` Fleet row: ratio survives, `retry.floor` is divided by `fleet.instances` with remainder warnings (`TestRetryFloorIsDividedByInstancesAndTheRatioAndCapAreNot`), `retry.bucket_cap` is per-instance (stated limit 4); no retry metric carries an unbounded label (only fixed `reason` / `outcome` enums).
- **Users:** Retry adds no per-client or per-tenant state beyond two fields on the single active `request` (`attempt`, `retryOver`) and reuses the bounded per-tenant admission queue.
- **Unbounded result sets:** Not applicable to chunk 12's retry core; once any reply byte has been relayed (`req.relayed > 0`), `reachedFor` returns `work.Yes` so `PreForwardOnce` never retries after a partial reply (`TestRetryNeverAfterARelayedByte`).
- **Compounds:** Retry on a path that can leak or double-apply is prevented by requiring explicit zero-byte `EvDBWriteRefused` (`Reached == No`), forbidding all in-transaction retries (`RefusedInTx`), closing/dirtying the failed connection before re-enqueueing, and clamping timers to `arrival + timeouts.statement`; the ablation check fails to assert duplicate writes directly (Finding 1).
