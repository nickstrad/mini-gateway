# The coalescer: core, engine wiring, and scenarios (chunk 11, 2026-11-27)

Reference notes before touching `internal/coalesce`, the engine's coalesce stage, or the coalescer scenarios. Full record: `agent_work/chunks/c11-coalescer/NOTES.md`.

## The core (`internal/coalesce`, determinism-linted, race-listed)

- `coalesce.New(cfg)` returns a `*Table`. Every method takes virtual time `now` and first expires flights and no-share entries due at or before `now`: `Join(now, id, *work.Unit)`, `Started(now, flight)`, `Stored(now, flight, n) bool`, `Finish(now, flight, Result)`, `Leave(now, id, LeaveCancel|LeaveGone)`, `Sweep(now)`, and `Shutdown(now)`. Side effects affecting other requests are queued as notices; drain `TakeNotice()` after every call.
- `Join` returns one of five verdicts: `Pass` (not eligible, key on the no-share list, duplicate member, or flight table full), `Lead` (own a new flight and enter the admission queue), `Follow` (wait on an existing flight with no queue slot and no connection), `Hold` (strict mode: own the next flight waiting behind a running read until `NoticeStart`), or `Refuse` (`53M04` at `MaxWaiters`).
- Eligibility inspects only the classifier's flags and key presence, never SQL text: `auto` requires `Unit.Shareable`, `hinted` requires `Unit.Hinted`, and both require `Unit.HasKey`. `keyOf` encodes `Unit.Key` as an 8-byte big-endian tenant length, the tenant bytes, and the exact statement bytes (`splitKey` decodes it for the hot-key snapshot), so no two distinct `(tenant, text)` pairs collide.
- Each key holds at most two flights: one current flight (queued or running) and, in strict mode, one held flight waiting behind a running read. Relaxed mode joins the running read. Every flight's deadline is `Config.Deadline` (`timeouts.statement`) from creation; flights sit in a creation-ordered doubly linked list so the head is always the next expiry (`O(1)` `Next`). Deadlines and no-share expiries saturate at the largest `Instant` (`after`).
- When an owner leaves with followers remaining, `Leave` hands ownership in `O(1)` to the newest follower (`LeftHandoff`). Only when the last member leaves (`LeftLast`) does the flight end so the engine cancels the database work. A leaver is removed immediately, so a result applied after the leave at the same instant never reaches it.
- Reply bytes exceeding `MaxReplyBytes` detach the flight: followers receive `NoticeRefused` (`53M04`), and the key enters a fixed-size FIFO no-share ring for `NoShareFor` (evicting the oldest key when full). A reply ending with a status other than `'I'` (such as a hinted `BEGIN`) detaches the same way (`CapUnshareable`).
- Test-only plants: `PlantStrictJoinsRunning`, `PlantAnyLeaveCancels`, `PlantLeaverGetsResult` (the fuzz plant), `PlantNoWaiterCap`, `PlantNoReplyCap`, and `PlantSafeReadDoor`.

## The engine (`internal/proxy/coalesce.go`)

- `Engine` installs `CoreCoalescer` when `proxy.Config.Coalesce.Mode != off` (or when `Seams.Coalescer` implements `FlightTable`). A zero `proxy.Config` keeps `NoCoalesce`, leaving earlier tier S specs unchanged. The binary defaults to `coalesce.mode: auto`, `join: strict`, and `key_scope: all-tenants`.
- Limit of that default: the safe shape trusts the database objects named in a query, so a view, a user-defined operator, a function shadowing an allow-listed name, or a row-level security policy that hides a side effect or per-call result is shared like any read unless the operator sets `coalesce.mode` to `off` or `hinted` (also stated in `docs/safe-shape.md`, "Limits").
- "At most one in-flight read per key" holds among the flights `Table` owns. Three counted cases sit outside it and pass unshared: a cancelled read still finishing on Postgres (`flight_ends{outcome="cancelled"}`), a key on the no-share list (`passed{reason="no-share"}`), and an arrival at a full flight table (`passed{reason="full"}`).
- A flight's owner waits in its tenant's admission queue (`cpQueued`). At its flight deadline, `coalExpireOwner` must remove it via `expireQueued` (`admission.Queues.Expire`, counted as a deadline shed) rather than `unqueue` (`RemoveAt`), keeping `admission.Queues.ShedCount()` equal to `Engine.Snapshot().Shed`. `coalStart` returns early once `e.stopping` is set so `Shutdown` never forwards new SQL, and refuses promotion with `53M03` (`engine.coalesce_promoted_refused`) when `e.breakerOpen()` is true (open or half-open).
- While storing (`req.store`), the owner buffers reply bytes up to `coalesce.max_reply_bytes` (validated to at most half of `limits.reply_buffer` so relay high-water bounds hold). At `ReadyForQuery`, the owner receives the stored bytes and the database's end marker, and each follower receives a reference to that same stored slice plus its own `ReadyForQuery 'I'`. Database reads are never paused for a slow follower while storing.
- Followers sit in phase `cpCoalesced` and are counted in `Snapshot.Coalesced`, giving engine conservation `accepted = completed + failed + shed + queued + in_flight + coalesced`.
- Stage hooks in shared files are one line each: `startRequest` (`coalJoin`), `forward` (`coalSent`), `relayed` (`coalStoring`), `relayEvents` (`coalSawError`, `coalReady`), `statementLost`, `shed`, `refuseWaiting`, `clientCancel`, and `closeClient`, plus `Invariants`, `Quiesce`, and `Shutdown`. `Invariants` also checks that `e.coalT` is armed at `Table.Next()`.
- Errors: a failed flight shares the owner's error row (`08006`/`08007`, `53M01`, `53M03`); a flight hitting its deadline answers `53M01` if never sent, or the statement-deadline row if running; a waiter's own cancel answers `57014` (`ErrRowCancelledQueued`); waiter and reply caps answer `53M04`.

## Joined with the fair dispatcher (chunk 9) and the retry policy (chunk 12)

- A flight's owner occupies one queue slot in its tenant's ring and holds one database lease; followers hold neither. Under `key_scope: all-tenants`, followers of other tenants ride the owner's lease without spending their tenant's share or marking their tenant active.
- Each request stores the tenant it was queued under (`request.tenant`). Queue push, checkout, and lease start charge `request.tenant`, `lend` records it in `dbConn.lastTenant`, and every lease-end path reports `d.lastTenant` rather than `c.tenant`. A cross-tenant owner handoff therefore keeps the queue slot and lease charge on the first owner's tenant until the lease ends; reporting `c.tenant` at release would report a lease end without a matching start.
- `statementLost` checks `!e.flightGone(req)` (never retrying a flight whose flight deadline already fired) and offers a zero-byte loss to the retry policy before sharing an error. If granted, `coalRetried` clears buffered state and `rerun` re-queues the owner while waiters stay attached and receive the retry's outcome once. `Table` keeps the flight in `stateRunning`, so strict-mode arrivals wait in a held flight behind it. If the policy declines (budget, breaker, deadline, second loss, or `off`), every waiter gets the owner's row once. The retry budget counts one first attempt per flight; followers are never forwarded.
- A retried owner waiting in its tenant queue ends at the earlier of the flight deadline and the request deadline (`retryClamp` on `c.queueT`); both paths answer all waiters via `shed` → `coalRefused`. The breaker re-check at every `dispatch` refuses it via `refuseWaiting` → `coalRefused` (`53M03` to every waiter).

## Scenarios

- `test/e2e/c11_coalesce.go` (`CoalesceScenarios()`, with the four fairness/retry join scenarios of `c11_join.go` appended) defines 27 tier S scenarios across both join modes, each with replay determinism checks and an ablation arm (coalescer off, a core plant, or retry policy off) that must fail the scenario's check. All 27 scenarios—`coalesce-results-*` included—run with admission queues (`RuleTimeout` sized to target `15 s` and interval `20 s` so the 1,000-read ablation arm does not shed, since the binary's `5 ms` target sheds those bursts) and the pool core; `coalAdmissionOK` verifies core sheds equal engine sheds. `TestScenarioCoalesce` caps seeds at 10 (3 for the 1,000-client hot key) unless `MG_C11_FULL_SWEEP=1`; the 1,000-client hot-key scenarios run only with `RUN_DIR` set or `MG_C11_HEAVY=1`, and `internal/obs/simrun` runs `coalesce-hot-key-strict` plus its ablation arm once outside `-short` so its `reads.sql` runs in G3.
- Database reads are counted from `Fake.StatementLog()` (`KindRead`, exact `Text`); interval overlap on `[Start, End)` measures concurrent reads. Because the fake reads a row's value when service starts, the relaxed read-your-own-write window is observable in tier S.
- Tier R (`test/e2e/c11_tierr_test.go`) uses views over `pg_sleep` (`c11slow`, `c11long`, `c11kv`) whose query text stays inside the safe shape, and counts completed reads via `pg_stat_statements.calls` deltas for the exact normalised query (cancelled statements are not counted). The tier R harness sets `coalesce.mode: off` on gateways using `lease.reset: on-switch` because `on-switch` with `all-tenants` is refused while coalescing is on.
- `Spec.Fairness` configures tenant weights and `Spec.Relay` places the dooming relay in front of the fake (`Path` must be nil because both use `BeforeProxy`). Calling `DoomAllAt` shortly before a burst forces a zero-byte write refusal on the first write by construction, since connections idle under `pool.check_after_idle` are lent without a health check.

## Arrival and ownership across strict holds

- A strict-mode held flight's owner sits in phase `cpCoalesced`, the same phase as its followers, so its departure bypasses `coalHandoff`. When `Depart` returns `LeftHandoff`, `coalLeave` copies the departing owner's `request.arrived` onto the successor before draining notices; repeated held handoffs carry that same original instant forward. Promotion updates `req.enq` for queue-wait measurement while leaving `req.arrived` fixed to bound retries, preventing a newest-follower handoff from extending a retry past an earlier follower's deadline when `coalesce.deadline > timeouts.statement`.
- A held flight has no queued-under tenant and `attempt == 0`; promotion enters the surviving owner's tenant queue for the first time. Queued and active handoffs instead transfer the whole `request` struct via `coalHandoff`, retaining its original `arrived`, charged `tenant`, and retry `attempt`, while `dbConn.lastTenant` preserves the lease-end tenant charge. `TestRepairHeldHandoffsPreserveTheOriginalArrival` and `TestRepairRepeatedRetryHandoffsKeepTheAttemptAndTenant` cover single and repeated disconnect/cancel handoffs across held, queued, and active states.
- In `TestRepairRandomFlightsRetriesDeadlinesAndBreakerTransitionsKeepTheInvariants`, each event asserts that every promotion occurring while the custom breaker is open increments `CoalescePromotedRefused` in that same event; a run-end coverage count alone does not prove no open-breaker promotion was forwarded, while a blanket ban on all writes would wrongly reject ordinary first attempts admitted before the custom breaker opened.
