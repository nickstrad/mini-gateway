# Reject list and function allow-lists

Generated by `scripts/gen-docs.sh` from `internal/pgwire/rejectlist.go`. Do not edit by hand: a test fails when this file differs from the code, and another test classifies every example below.

A rejected statement is answered with `ERROR 0A000` (error row `unsupported-feature`) and nothing is sent to the database. A `Query` message is rejected as a whole when any statement in it is rejected. The classifier is a lexer, not a parser: a function, view, rule or default that hides one of these features is not seen.

## Rejected

| Reason | Feature | Why | Example |
| --- | --- | --- | --- |
| `session-set` | Session `SET` (every form except `SET LOCAL`, `SET TRANSACTION`, `SET CONSTRAINTS`; includes `SET SESSION ...`, `SET SESSION CHARACTERISTICS AS TRANSACTION ...`, `SET ROLE`, `SET SESSION AUTHORIZATION`, `SET TIME ZONE`, `SET NAMES`, `SET SCHEMA`, a custom setting whose first part is `local`, `transaction` or `constraints` such as `SET local.x = 1`, and `SET LOCAL NAMES`); `UPDATE pg_settings ...` in any statement that names `pg_settings` and contains `UPDATE`; and any statement containing `SET` or `RESET` that names `standard_conforming_strings` or `client_encoding`, `SET LOCAL` included, because both change how Postgres lexes the statements that follow | The setting outlives the transaction and would follow the pooled connection to the next client. | `SET search_path = app` |
| `reset` | `RESET name`, `RESET ALL` | Changes session settings that outlive the transaction. | `RESET statement_timeout` |
| `prepare` | `PREPARE name AS ...` | A prepared statement lives on the connection, not in the transaction. | `PREPARE q AS SELECT 1` |
| `execute` | `EXECUTE name` (also after `EXPLAIN` and in `CREATE TABLE ... AS EXECUTE`) | Needs a prepared statement from an earlier exchange, which may be on another connection. | `EXECUTE q` |
| `deallocate` | `DEALLOCATE` | Removes connection-level prepared statements. | `DEALLOCATE ALL` |
| `listen` | `LISTEN` | A subscription lives on the connection; notifications would reach whichever client holds it next. | `LISTEN jobs` |
| `unlisten` | `UNLISTEN` | Same as `LISTEN`. | `UNLISTEN *` |
| `cursor-with-hold` | `DECLARE ... WITH HOLD` | A holdable cursor survives the commit and stays on the connection. | `DECLARE c CURSOR WITH HOLD FOR SELECT 1` |
| `temp-object` | Temporary objects: `CREATE [GLOBAL\|LOCAL] TEMP\|TEMPORARY TABLE/VIEW/SEQUENCE`, `SELECT ... INTO TEMP`, `CREATE OR REPLACE TEMP VIEW`, and any reference to the `pg_temp` schema | Temporary objects belong to the session and would be visible to, or missing for, the next client. | `CREATE TEMP TABLE t (a int)` |
| `advisory-lock` | Session advisory-lock functions: `pg_advisory_lock`, `pg_advisory_lock_shared`, `pg_try_advisory_lock`, `pg_try_advisory_lock_shared`, `pg_advisory_unlock`, `pg_advisory_unlock_shared`, `pg_advisory_unlock_all` (any schema, quoted or not) | A session lock is held until released or the session ends, not until the transaction ends. | `SELECT pg_advisory_lock(42)` |
| `set-config` | `set_config(name, value, is_local)` whose third argument is not the bare literal `true`, or whose first argument is not a plain string literal, or names `standard_conforming_strings` or `client_encoding` | With `false` (or anything that might be `false`) the change is session-level; a setting name the classifier cannot read might be one that changes how later statements are lexed. | `SELECT set_config('search_path', 'app', false)` |
| `discard` | `DISCARD ALL\|PLANS\|SEQUENCES\|TEMP` | Resets session state that other clients' work may rely on; the proxy owns connection hygiene. | `DISCARD ALL` |
| `load` | `LOAD 'library'` | Loads a shared library into the backend process for the rest of the session. | `LOAD 'auto_explain'` |
| `copy` | `COPY` in any direction | The copy sub-protocol is not relayed by the proxy. | `COPY kv TO STDOUT` |
| `two-phase` | `PREPARE TRANSACTION`, `COMMIT PREPARED`, `ROLLBACK PREPARED` | Two-phase commit leaves a prepared transaction outside the session that the proxy cannot track. | `PREPARE TRANSACTION 'tx1'` |
| `extended-protocol` | Every extended-protocol message (`Parse`, `Bind`, `Describe`, `Execute`, `Close`, `Flush`, `Sync`) and `FunctionCall` | v1 speaks the simple-query subset only; messages are discarded until `Sync`. | (a Parse message) |

## Allowed because they are transaction-scoped

| Form | Why | Example |
| --- | --- | --- |
| `SET LOCAL ...` | Lasts until the end of the current transaction. | `SET LOCAL statement_timeout = '5s'` |
| `SET TRANSACTION ...` | Applies to the current transaction only. | `SET TRANSACTION ISOLATION LEVEL SERIALIZABLE` |
| `SET CONSTRAINTS ...` | Applies to the current transaction only. | `SET CONSTRAINTS ALL DEFERRED` |
| `set_config('name', value, true)` | The bare literal `true` makes the change transaction-local; the name must be a plain string literal. | `SELECT set_config('search_path', 'app', true)` |
| Transaction-level advisory locks: `pg_advisory_xact_lock`, `pg_advisory_xact_lock_shared`, `pg_try_advisory_xact_lock`, `pg_try_advisory_xact_lock_shared` | Released at the end of the transaction. | `SELECT pg_advisory_xact_lock(42)` |
| `DECLARE ... CURSOR` without `WITH HOLD` | Closed at the end of the transaction. | `DECLARE c CURSOR FOR SELECT 1` |
| `NOTIFY` and `pg_notify(...)` | Delivered at commit; harmless without `LISTEN`, which is rejected. Never read-only, never coalescable. | `NOTIFY jobs, 'x'` |
| `LOCK TABLE` | Released at the end of the transaction. | `LOCK TABLE kv IN SHARE MODE` |

## Words that end a proof

Read-only-provable fails when any of these appears as an unquoted word anywhere in the statement: `insert`, `update`, `delete`, `merge`, `truncate`, `create`, `alter`, `drop`, `grant`, `revoke`, `comment`, `call`, `do`, `copy`, `lock`, `vacuum`, `analyze`, `analyse`, `reindex`, `cluster`, `refresh`, `import`, `security`, `reassign`, `notify`, `listen`, `unlisten`, `set`, `reset`, `discard`, `prepare`, `execute`, `deallocate`, `declare`, `begin`, `start`, `commit`, `rollback`, `abort`, `savepoint`, `release`, `checkpoint`, `load`, `into`, `operator`, `nextval`, `setval`; or `FOR` followed by `update`, `share`, `no`, `key` (a locking clause).

Coalescable fails when any of these appears as an unquoted word: `current_date`, `current_time`, `current_timestamp`, `localtime`, `localtimestamp`, `current_user`, `session_user`, `user`, `current_role`, `current_schema`, `current_catalog`, `system_user`, `tablesample`.

Operators allowed in a read-only-provable statement: `+`, `-`, `*`, `/`, `%`, `^`, `=`, `<`, `>`, `<=`, `>=`, `<>`, `!=`, `\|\|`, `~`, `~*`, `!~`, `!~*`, `~~`, `~~*`, `!~~`, `!~~*`, `@>`, `<@`, `&&`, `->`, `->>`, `#>`, `#>>`, `?`, `?\|`, `?&`, `@@`, `@`, `&`, `\|`, `#`, `<<`, `>>`, `=>`.
